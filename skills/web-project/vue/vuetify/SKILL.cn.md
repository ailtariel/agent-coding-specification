# Vuetify

尚未加载时应用 [Vue 个人约定](../SKILL.md)。这些是个人实现选择，不代表 Vuetify 强制要求这种架构。

## 布局与样式

- App 负责 `VApp`；layout 负责 `VLayout`、注册的外壳区域和 `RouterView`；每个路由 page 负责自己的 `VMain` 与主要滚动区域。保留项目已经明确采用的其他架构。
- 外壳偏移、顺序、尺寸和定位通过布局注册与组件 API 表达，不用 margin、fixed 定位或子页面 CSS 重做这些职责。
- 横向和纵向分组优先 Flex；确需二维对齐或跨行跨列时使用 Grid。优先选择合适的 Vuetify 容器和表面组件，不从通用包装节点开始；需要响应式分栏时才使用列布局。
- App bar 使用匹配的 Vuetify 标题、导航、间距、分隔与 slot 能力，不重做它们的几何行为，也不加入没有布局职责的组件。
- 自定义视口判断前，优先使用已配置断点、响应式工具类和组件属性。减少动态效果等媒体特性是独立需求。

## 输入与反馈

- 优先使用内置 loading 反馈，只有内置能力无法满足定制需求时才使用自定义指示器；同一操作不同时显示两者。
- 不默认给输入控件包裹表单。需要校验、协调提交等表单专属能力时才使用，并保留所需键盘行为。
- 输入控件自身的操作优先使用内置操作，其次使用公共 slot；交互确需分离时才使用独立同级控件。作用于筛选组的操作归筛选组所有。
