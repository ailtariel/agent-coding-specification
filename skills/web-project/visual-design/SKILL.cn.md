# 视觉设计

在用户要求的范围内应用以下视觉呈现偏好。RTL/LTR 与混合方向文本属于 Web 前端编程规范。

设计或调整毛玻璃材质时，阅读[毛玻璃视觉设计](frosted-glass.md)：区分面板透射与背景磨砂，按材质职责调节效果并进行反向检查。

改善已有界面的杂乱、拥挤或失衡问题时，使用 [Refactoring UI](refactoring-ui/SKILL.cn.md) 诊断症状并对照局部修正。

## 范围、层次与分组

- 视觉调整应保留既有行为、信息和空间约束。仅调整容器时，可以拆分或合并容器，但不移动内容区域或改变其顺序。
- 除非用户要求重新设计，否则沿用既有视觉语言。每个页面都应有明确的视觉层次，避免同等突出的高亮元素分散各处、争夺注意力。主体不突出时，先降低竞争元素的强调程度，而不是继续增加高亮。
- 找出页面及每个区块的内容主体。在布局约束内，优先将可用空间分配给主体内容，次要内容保持紧凑、低强调；不要让过大的标题、辅助面板或装饰性留白挤占主体内容空间。
- 同一任务的内容应放在一起，避免将页面切成零碎的视觉区块，也避免每个标签、控件或统计项都独占一张卡片。
- 连续大面积内容仍需根据内容关系建立内部层次。可以使用克制的背景差异、字号、间距、留白或分隔线区分有意义的分组，同时保持整块内容的视觉融合与连续性。既避免没有层次的内容墙，也避免分隔过强、让相关内容显得割裂。
- 谨慎使用边框，尤其避免重复或过密的多层边框嵌套。优先用间距和字体层级分组，再考虑围合边框；不要在同一分界处叠加边框、阴影和强烈的背景变化。保留识别控件或焦点所必需的边界。
- 只有任务允许且保留键盘和触控访问时，才将次要说明移入提示浮层；必要操作说明、错误信息和影响决策的内容保持可见。

## 表面与交互配色

- 添加覆盖样式前，先检查主题和组件默认值。重复出现的视觉问题通过语义令牌或共享组件解决；局部例外留在其所属组件。前景色与边框色应结合实际所在表面选择。
- 降低文本强调程度时，调整前景色或组件变体，不要降低整个容器的不透明度：容器透明度会同时改变图片、嵌套控件、焦点指示和禁用状态。
- 次要控件静态时保持低强调，同时保留可区分的悬停、键盘焦点、选中和禁用状态。减轻视觉重量不能抹去焦点或状态信息。
- 对照参考主题时，检查各个相关表面作用域内的计算样式与 CSS 变量。只看根变量和截图会遗漏上下文覆盖、透明度及交互配色。区分实测值、推断的语义名称和适配后的取值。

## 视觉验证

- 在与改动相关的已支持主题和状态下检查受影响表面；浮层继承了改动样式时，也要检查浮层。密度、截断、溢出或滚动可能受影响时，使用真实长度或空内容检查，并检查有代表性的悬停和键盘焦点状态。
- 说明实际检查过和仍未验证的呈现效果。不要仅凭观感宣称对比度合规，也不要为了整页统一而重做未受影响的区域。
