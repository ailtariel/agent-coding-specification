# Refactoring UI

从 [s0xDk/refactoring-ui-skill](https://github.com/s0xDk/refactoring-ui-skill/tree/48872143abb0a8feb6d9bf58e222afbd800210b0) 筛选改写的视觉诊断流程；上游笔记源于 Adam Wathan 与 Steve Schoger 的《Refactoring UI》。许可证见 [LICENSE](LICENSE)。以下是有适用条件的设计方法，不是强制审美，也不是原书副本。

## 先明确哪里不对

- 将模糊评价转成可观察的关系：什么元素抢在主要内容之前吸引注意，哪个标题像是属于错误分组，或哪里出现了材质、对齐上的突变。下表中的原因只是待验证的假设；先检查实际视图、内容与计算样式，再选择修正方向。
- 确认受影响区域的主要任务，以及已有的字体、间距、颜色和层次约定。保留行为、信息和用户限定的布局边界。视觉整理本身不授权隐藏标签、移除控件、改变流程或替换设计系统。
- 在相同内容、视口、主题和状态下对照局部调整。先修正怀疑的原因，再考虑装饰。选择令牌时，将当前值与已有的相邻选项对照；仅当它们不能表达目标关系时才引入新值。

## 按症状诊断

| 观察到的症状 | 优先检查 | 局部调整方向 |
| --- | --- | --- |
| 主要内容反复放大后仍不突出 | 次要表面、图标或操作是否拥有相近的视觉重量 | 先降低竞争元素的强调程度，再考虑继续放大主要内容；保留文字可读性和控件可辨识性 |
| 大标题压过内容，辅助文字却很小 | 是否几乎完全依靠字号建立层级 | 收拢字号差异，用字重和前景色重新分配强调；语义上的标题不必在视觉上占据主导 |
| 标题或字段标签像是属于另一组内容 | 组间与组内间距是否难以区分 | 调整相关间距关系，不统一增加所有内边距；保留预期的信息密度 |
| 危险操作压过日常主流程 | 是否把语义严重程度当成操作优先级 | 保留警示含义并降低视觉突出程度；在该操作成为主任务的确认场景中，再考虑强强调 |
| 彩色表面上的文字显灰、像禁用态 | 是否直接复用了中性灰或透明前景，而未结合当前表面检查 | 尝试与表面色相关的明确前景色并验证对比；不将此推广成禁止所有灰色文字 |
| 状态标签抢占密集列表的注意力 | 饱和实色填充是否让每个状态都像主操作 | 对照浅色表面与较深的彩色文字，保留可辨识的状态差异；检查实际前景与表面的组合 |
| 图标压过文字，或边框不是看不见就是太重 | 相同颜色下，填充面积或笔画重量是否差异很大 | 同时调整重量和对比：弱化厚重图标，或对照更柔和、略粗的边框；不能削弱识别控件所必需的边界 |
| 同一行不同字号的文字显得错位 | 几何居中是否只对齐了盒子，而未对齐阅读基线 | 对文字比较基线对齐；混合控件或图标的行仍按实际视觉效果决定是否居中 |
| 表单在宽屏上摊开，或在中间断点反而更宽 | 百分比栅格是否取代了内容实际需要的宽度 | 约束内容宽度，将剩余空间交给适合伸缩的区域；不因此要求所有布局都使用固定侧栏 |
| 截图或图标在展示尺寸下显得粗糙 | 是否过度缩小细节，或过度放大小尺寸图形 | 使用相关区域裁剪或较窄视口截图；选择适合目标尺寸的图形，不等比例缩放所有细节 |
| 图片上的文字在某个裁剪下清晰，换一个就难读 | 文字后方的局部图像亮度是否变化很大 | 通过遮罩、局部对比处理或稳定的文字表面控制背景；检查不同裁剪，不依赖单张截图 |

## 材质与配色修正

- 悬浮表面周围出现脏灰光晕时，区分宽而柔和的投射阴影与紧贴物体的接触阴影。采用物理层次表达时，距离增加可以让投射阴影扩散，同时减弱接触阴影；同步加重所有参数只会让物体变沉。扁平视觉语言不必增加这套效果。
- 采用定向光照线索时，对照高光边缘与物体表面的亮度。凸起边缘与凹入边沿表达不同形态；将深色表面的高光直接搬到浅色字段上，可能变成多余的深色边框。保持光照方向一致，不给所有表面套用同一阴影配方。
- 色板出现缺口时，从实际缺失的角色推导候选值，例如操作填充、辅助表面及其文字。先将它们放在一起检查，再补充中间色阶。不引入上游整套令牌表，不规定固定色阶数量，也不把数值等距当成感知等距。
- 深色主题失去层次时，先检查相邻表面的明度与边界，再考虑增加阴影不透明度。如果提亮表面恢复了分隔，应重新检查其辅助文字：改善一处边界可能降低另一处对比。不要机械反转浅色调色板。
- 透射、模糊及玻璃材质的问题使用[毛玻璃视觉设计](../frosted-glass.md)处理，不以更重的阴影或彩色面板填充补偿背景信息不足。

## 验证诊断是否成立

在相同状态下重新观察原始症状，再用有代表性的长内容、相关宽度和已支持主题检查受影响关系。降低强调程度时检查焦点与选中状态。说明视觉变化与实际检查过的内容；仅修改 CSS 不能证明效果改善。问题解决后停止，不为了套用所有方法而继续修改整页。
