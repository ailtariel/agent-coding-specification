# 大型任务

仅在对应任务中读取；遵循核心编码规范的授权、范围与验证约束。


- [large-task-threshold] 当复杂依赖或实施阶段需要保留时，使用相称的分阶段计划。多个独立子任务并不自动需要正式文档或确认；按核心规范的授权规则继续。
- [default-phase-flow] 已有实施授权时自动推进阶段，不逐阶段确认。发现新的阻塞决策时仅暂停依赖部分，并继续独立工作。
- [phase-workflow] 每个实施阶段至少按以下顺序包含：
  1. 代码修改
  2. 审查，包括功能是否正常、是否遵循设计和实施文档、是否引入需求范围外的修改，以及是否违反本规范相关规则。发现偏差时，修复后才能进入下一阶段。
  3. 最小必要验证
  4. 在实施文档中简要记录实施状态
  5. 用户要求或已授权 workflow 包含提交时，进行 Git commit。每阶段优先一个内聚提交，不拆分无意义小提交。
